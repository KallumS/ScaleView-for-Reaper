## What the session did

### Settled "why not just match a table of chords"

A second script, `ScaleView Pattern`, was built as a controlled comparison -
Pro with the chord reader replaced by a pattern-matching engine - so the two
approaches could be judged side by side rather than argued about. The user
tested both against Scaler, Pro won outright, and Pattern was **deleted**. Its
measurements are kept, because the question will be asked again.

**100% against 23.5%** over 17,688 voicings; 99.999% against 93.276% on the
music21 core corpus. The table's failures were one failure repeated: a pattern
wins while leaving a note unexplained, so `G D F` reads `G5`. Raising the
penalty for that helps to 23.5% and then the engine drops below its own
threshold and gives up instead - a ceiling, not a tuning problem.

→ decision [0001](../decisions/0001-read-chords-rather-than-look-them-up.md)

### Measured the naming against five more corpora, and against humans

Two different questions, deliberately kept apart: *does the symbol account for
exactly the notes played* (objective, checked by a theory-only checker) and
*does it agree with the name somebody else gave those notes* (a matter of
notation, where usually neither side is wrong).

Objective: **1,216,277 sonorities across six corpora, twelve misses**, every
one an eight-or-more pitch-class cluster hitting the deliberate guard in
`detectChord`. Not one is a misnamed chord.

Against humans: jazznet's generated labels (63.1% identical, all differences
in three explicable classes), and the Roman-numeral analyses carried by DCML
and When in Rome (91.1% and 92.0% on the root). The striking figure is the
bass: **whenever the analyst's bass is the lowest note sounding, Pro names it,
on every one of 111,723 slices.**

Two of the corpora are CC BY-NC-SA. They were cloned, scanned, scored and
discarded; nothing from any corpus is in this repository.

### Compared Pro against Scaler 3 on 24 chords

Twelve in major keys, twelve in natural minor, reported back by the user and
reproduced by `tools/scaler_cases.py`. Every one of the 48 names - both
engines, all 24 chords - accounts for exactly the notes played. It was never
anything but a disagreement about which root to name.

Four rules came out of it and are implemented: the doubled-root bass rule, a
`dim7` carrying a ninth reads `dim9`, a minor sixth loses to the
half-diminished on its third, and a third beats a shape with none.

Two nulls came out of it as well, and they are the more valuable half:

- **Scaler does not use the key to choose the root.** This had been written
  into `CLAUDE.md` as a probable rule, with the experiment that would settle
  it written beside it. The experiment cost one chord in two keys and the
  answer was no.
- **Weight-tuning cannot buy Scaler's remaining roots.** Swept 36
  combinations of the two weights that looked responsible. The ceiling is
  three more chords than shipped, each bought with collateral, and no setting
  is stable.

→ decision [0002](../decisions/0002-the-scale-only-breaks-a-draw.md),
[0003](../decisions/0003-the-bass-is-the-lowest-note-bar-a-doubled-root.md)

### Fixed two real bugs, both reported from REAPER

**The ring was responding to window resizes, not key presses.** The user's
exact words - *"D E ab light up but B doesn't - when I resize the window B
lights up but doesn't turn off for a few seconds"* - are what located it. The
poll redrew on a change to the chord *name*, and adding B to D E Ab leaves the
name `E7/D` because a missing fifth is silent.

**Which note is the fifth was guessed, not costed.** With both a flattened and
a raised fifth sounding and no perfect one between them, `core()` took the
flattened one greedily, so C E F# G# B read `Cmaj7b5b13`. Both readings are
built now and the cheaper wins. Found by running Wikipedia's *List of chords*
through the engine.

→ decision [0005](../decisions/0005-redraw-on-the-held-set.md)

### Standardised the colours

Background `#23272E`, lit-circle note names `#14171C`, played-note ring
`#FFF200`, and Gold swapped out of the highlight menu for White. The full
house scheme - carriers, the eighteen-entry ramp, both carry-over rules - is

All four of ScaleView's greys already satisfied the ramp's `R < G < B`, which
is why the scheme fitted. Two were near-misses of ramp entries and were
snapped; two are deliberately still off it, and both are decisions rather than
tidy-ups.

→ decision [0006](../decisions/0006-the-played-note-ring-is-unconditional.md),

## What went wrong, and what it cost

The useful part of the log. Each of these is now a line in *Lessons learned*.

- **A contrast calculation was right about the wrong surface.** White reads
  1.6:1 to 2.4:1 against a highlight fill, which is true, and a conditional
  ring was built on it. Both ring strokes are drawn *outside* the filled
  circle, on the background, where white read 17.4:1. The user's report was
  blunt - *"the ring highlighting is completely broken"* - and correct.
- **A harness that forces the frame it then reads cannot see a redraw bug.**
  The suite's `label()` helper toggles `gfx.w`, and `play()` called it, so
  every chord assertion in the file was reading a frame the test itself had
  demanded. The bug shipped. Ask what your harness supplies that the real
  thing does not.
- **A test asserting a fallback can pass for free.** The plugin's new
  highlight-fallback test was first written with a hand-built state block that
  the processor rejected outright - leaving the default in place, which is
  exactly what the test asserts. It round-trips a real saved state now and
  checks the root and scale came through too.
- **`head -N` truncated a script before it wrote its output**, and a stale
  results file from an earlier run was then analysed as if it were the new
  one. Redirect to a file; do not pipe into `head`.
- **`git stash` reverted the test along with the code**, so the "does this
  test fail on the old code" check proved nothing. Restore only the file under
  test, with `git show HEAD:...`.
- **A claim in `CLAUDE.md` was treated as evidence** more than once, and more
  than once described a version that no longer existed. It is a lead to
  verify, not a fact to act on.
